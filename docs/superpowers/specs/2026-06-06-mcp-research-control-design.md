# MoneyPrinter MCP Research + Control Design

Date: 2026-06-06

## Goal

Build a stdio MCP server for MoneyPrinter so Claude, Codex, and other MCP clients can use the local app as tools. The first scope is research plus video-generation control. The MCP server will not start MoneyPrinter; the backend must already be running at `http://127.0.0.1:15001`.

## Non-Goals

- Do not build a separate HTTP MCP sidecar.
- Do not start or manage `start_hub.bat`, uvicorn, or frontend processes.
- Do not expose config editing, secrets, browser profiles, cookies, tokens, account caches, or generated media file writes.
- Do not call provider APIs directly from MCP tools.
- Do not read or write `config.json` directly.

## Recommended Approach

Use a Python stdio MCP server as a REST bridge to the existing FastAPI backend.

This keeps MCP small and avoids duplicating MoneyPrinter runtime logic. The server validates backend health with `/system/status`, then calls existing endpoints. If the backend is not running, every tool returns a clear error with the expected URL and start command.

## Architecture

Add a single MCP entrypoint, tentatively `src/mcp_server.py`, plus small helper modules only if needed.

The MCP server will:

- Run over stdio for Claude Desktop, Claude Code, Codex, and compatible clients.
- Use `http://127.0.0.1:15001` as the default backend URL.
- Allow override via environment variable, for example `MONEYPRINTER_API_BASE`.
- Use existing FastAPI endpoints for all behavior.
- Return structured JSON-friendly data, not raw SSE streams.
- Keep long-running generation asynchronous by triggering the backend job and returning the `session_id`.

## Tool Set

### Health

`moneyprinter_status`

Checks backend availability and returns basic system status.

Backend route: `GET /system/status`

### Research

`research_create_session(topic?: string)`

Creates a research session.

Backend route: `POST /research/sessions`

`research_list_sessions()`

Lists research sessions.

Backend route: `GET /research/sessions`

`research_chat(session_id: string, message: string, mode?: "chat" | "research" | "ideas")`

Sends a message to an existing research session. Because the backend uses SSE, the MCP bridge will consume the stream internally, collect status/chunk/done events, and return a final object containing text, ideas, and status messages.

Backend route: `POST /research/sessions/{session_id}/chat`

`research_get_history(session_id: string)`

Returns conversation history.

Backend route: `GET /research/sessions/{session_id}/history`

`research_get_ideas(session_id: string)`

Returns saved ideas generated by ideas mode.

Backend route: `GET /research/sessions/{session_id}/ideas`

### Video Control

`youtube_list_accounts()`

Lists configured YouTube accounts so MCP clients can choose an `account_id` without reading local account cache files.

Backend route: `GET /accounts/youtube`

`youtube_create_draft(account_id: string, subject?: string, script?: string)`

Creates a draft generation session without starting the pipeline.

Backend route: `POST /youtube/{account_id}/sessions/draft`

`youtube_generate(account_id: string, subject?: string, script?: string, resume_session_id?: string, force_new_session?: boolean, regenerate_from_step?: string, publish_mode?: "manual_review" | "auto", auto_push_social?: boolean, script_language?: string, tts_voice?: string, enable_cc?: boolean, cc_mode?: "auto" | "script" | "whisper")`

Starts background video generation and returns the backend `session_id`. Default publish mode is `manual_review`.

Backend route: `POST /youtube/{account_id}/generate`

`youtube_list_sessions()`

Lists generation sessions.

Backend route: `GET /system/sessions`

`youtube_get_session(session_id: string)`

Returns session metadata, including stage, subject, script, image paths, audio path, and video path when available.

Backend route: `GET /system/sessions/{session_id}`

`youtube_cancel(session_id: string)`

Requests cancellation for a running generation.

Backend route: `POST /youtube/sessions/{session_id}/cancel`

`moneyprinter_logs(limit?: number)`

Returns recent in-memory logs for status polling.

Backend route: `GET /system/logs/history`

## Data Flow

Research flow:

1. MCP client calls `research_create_session` with a topic.
2. MCP client calls `research_chat` with mode `research` or `ideas`.
3. MCP server consumes backend SSE and returns final text plus any ideas.
4. MCP client can call `research_get_ideas` or use selected idea text as input for `youtube_generate`.

Generation flow:

1. MCP client calls `youtube_generate` with account, subject, script, and options.
2. Backend starts a background task and returns `session_id`.
3. MCP client polls `youtube_get_session` and `moneyprinter_logs`.
4. MCP client calls `youtube_cancel` when needed.

## Error Handling

- Backend unavailable: return a tool error containing backend URL and command hint: `start_hub.bat`.
- HTTP 4xx/5xx: return route, status code, and backend `detail` when present.
- SSE parse failure: return collected status messages plus parse error.
- Timeout: use conservative client timeouts. Research SSE can be longer than normal REST; generation trigger should stay short.
- Missing account ID: surface backend 404 instead of guessing an account.

## Security And Safety

- Do not expose config patch endpoints in first version.
- Do not expose delete session endpoints in first version.
- Do not expose push-now or schedule-publish tools in first version.
- Default generation stays `manual_review` to avoid accidental publishing.
- Return media URLs or metadata from backend only; do not write generated media from MCP.

## Verification Plan

Backend checks:

```powershell
python -m py_compile src\mcp_server.py
```

MCP smoke checks:

- Start MoneyPrinter backend with `start_hub.bat` or uvicorn.
- Run MCP inspector or a local stdio smoke script.
- Verify `moneyprinter_status` returns status.
- Verify `research_create_session` and `research_chat(mode="chat")` return text.
- Verify `research_chat(mode="ideas")` returns ideas.
- Verify `youtube_list_accounts` returns configured accounts or an empty list.
- Verify `youtube_list_sessions` returns session metadata.
- Verify `youtube_generate(..., publish_mode="manual_review")` returns `session_id`.
- Verify `youtube_get_session(session_id)` reports stage.
- Verify `youtube_cancel(session_id)` sets cancellation when a job is running.

## Implementation Notes

- Prefer the official MCP Python SDK if dependency installation is acceptable.
- Add the MCP dependency to `requirements.txt` only after confirming package name and import path.
- Keep tool schemas narrow and typed.
- Use existing log/status patterns; do not add a new runtime state store.
- Preserve current staged and modified user changes during implementation.
